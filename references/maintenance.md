# 维护与迁移

## 项目总台账

将既有规范台账作为`--ledger-out`时，生成器会读取、校验、合并、重建并替换该文件。若需保留原路径不动，用`--existing-ledger`指向原文件，`--ledger-out`指向新文件。

被替换的文件先备份到工作区`backups/时间戳/`。构建前后会检查源文件是否被改动；单个目标文件使用同文件系统原子替换。此机制不是多人协作锁，也不是Word与Excel之间的跨文件事务。项目应指定一个合并人，避免多人同时写同一主文件。

重建会应用配置样式，不保证保留人工的格式微调。只支持本技能v1.2规范表结构；额外工作表、额外列及旧数据版本会拒绝导入，防止丢失自定义数据。不要把复杂财务模型或带宏工作簿交给该工具更新。

## v1.1及其他旧格式

旧版单次访谈台账不能直接当作v1.2项目总台账导入。迁移前：

1. 备份原文件，列出全部记录、核实信息、证据及来源。
2. 配置本项目小组，将记录映射到一个归口及必要的协同组。
3. 将访谈型ID映射为稳定项目ID，历史ID保留在historical_id。
4. 逐条补核证据的speaker_role和utterance_type，尤其区分提问、建议、要求与现状。
5. 从映射后的工作JSON建立新台账，比较记录数量、原文、核实与确认信息，并测试引用和统计。
6. 确认后将旧格式移入历史归档，仅保留一份活跃的项目主台账。

不提供“忽略错误强行导入”的选项，不把无法识别的列直接删除。

## 版本升级

更新技能前备份本地目录，保留私有样式配置和品牌资源。仓库默认忽略`*.local.json`；安装更新时不要用公共默认样式覆盖组织已确认的私有资源。

完整测试命令：`python -m unittest discover -s tests -v`。结构、模板、公式或脚本改动后再做生成、重算和渲染检查。普通新增访谈无需每次重跑单元测试套件。
