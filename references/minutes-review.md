# 纪要独立内容评审

起草者把工作数据、草稿、语义检查包和原始材料交给未参与起草的项目人员或独立评审代理。评审者先阅读minutes-examples.md校准尺度，第一遍仅阅读拟交付正文，第二遍再回查原始材料。引用匹配、自动检查和起草者自检各自保留。

先单独通读拟交付正文，按项目成员的阅读场景判断是否可直接发给参会方。随后对照原始材料做事实复核。评审记录须分别写明“项目交付适用性”和“事实与证据”的结论及对应段落，两个维度均通过才可给出 PASS。复审关闭旧意见后仍须检查完整交付稿。

逐项检查：

- 项目交付适用性。发现原始转写异文、说话人判断、证据补录提示、内部顾问备忘，或未达成的建议进入已明确安排表，判 REVISE。核对待确认事项是否需要项目各方共同确认，内部编审问题移回工作区。复核时确认业务不确定性仍得到准确表达。
- 信息取舍。读完概述能复述最重要的发现和有明确归属的改进优先级。章节标题能表达业务发现，次要背景的篇幅与其用途相称。
- 标题与标签。逐条检查章节标题、子标题和加粗标签。发现“各管一段”“系统要贴现场”等口语化判断、归属不清的优先级或多个结论挤在同一标题时，判 REVISE。用业务议题标题承接内容，并在正文分别说明事实、观点及其归属。
- 结论句与主体。遮住短标签逐条读正文，任何关键结论须能独立理解。若正文只是片段拼接、靠括号补全，或以“受访方”反复代替已明确的业务主体，判 REVISE。核对称谓调整是否改变了观点归属或把个别意见升为共识。待确认事项须写明要确认的对象与口径。
- 归纳质量。正文解释发现的依据、影响和适用范围，区分事实、诉求、顾问归纳及决定。概述和正文各有作用，避免换词复述。
- 证据一致性。核对关键数字、口径、主体、时间及因果。正文仍待核实的数字或范围在概述中也须限定。逐条检查关键判断和明确行动，记录对应证据或缺口。
- 覆盖与可执行性。检查重要分歧、诉求和行动是否遗漏，待核实事项是否具体到需要补什么证据。责任和期限按明确约定记录。

评审者在工作区保存 minutes-review-result.json，包含评审人或代理身份、日期、被评审的工作数据文件及 SHA-256、PASS 或 REVISE、逐条意见和复核结果。意见注明段落、问题、原文定位及修订要求。发现关键结论无支撑、口径矛盾、重大遗漏，或需要读者从同级细节自行重建业务主线时判 REVISE。返工后评审者核对改动和原文，在新版本上记录结论。已评内容变化后重审，纯版式变化复查成品。

回归案例使用虚构材料。若材料提到计划准确率约 90% 且口径待核实，正文写成“总量准确率为 90%”应判 REVISE。若受访方明确优先处理质量，纪要却给物流工具和质量相同篇幅且概述遗漏该优先级，也应判 REVISE。修订稿须保留受访方归属、说明证据边界，并按对项目工作的影响调整篇幅。

## 当前评审记录与定稿入口

规则版本为 minutes-quality-v4。每轮评审重新读取当前规则。第一遍逐段记录段落的主要业务意思、主体是否明确、句子是否连贯，以及其进入项目纪要的价值。第二遍逐段核对来源、归属、范围和决定程度。PASS也须写明段落位置、判断及其依据，不能仅提交空comments或一句“通读无问题”。检查范围覆盖概述、所有业务段落、行动和待确认事项。

结果文件使用以下字段。paragraph_checks中的示意项必须替换为对当前稿件实际逐段检查的记录。

```json
{
  "rules_version": "minutes-quality-v4",
  "reviewer": "真实评审人员或代理标识",
  "independent": true,
  "reviewed_at": "实际时间",
  "data_sha256": "当前normalized-data.json的SHA-256",
  "minutes_sha256": "当前拟交付Word的SHA-256",
  "delivery_suitability": {"verdict": "PASS", "paragraph_checks": [{"location": "段落位置", "assessment": "主要业务意思与验收判断", "basis": "引用当前稿件文字并说明判断理由"}]},
  "evidence": {"verdict": "PASS", "paragraph_checks": [{"location": "段落位置", "assessment": "事实及归属核对结论", "basis": "原始材料定位和支持范围"}]},
  "synthesis": {"verdict": "PASS", "checks": [{"location": "业务归纳稿与对应正文", "assessment": "组织与覆盖判断", "basis": "来源与编排依据"}]},
  "section_coherence": {"verdict": "PASS", "checks": [{"location": "章节及相邻编号范围", "assessment": "整节主线及段落边界判断", "basis": "应合并或保留独立段落的具体理由"}]},
  "tracking_selection": {"verdict": "PASS", "checks": [{"location": "取舍记录与跟踪事项", "assessment": "重要性与承接判断", "basis": "实际筛选依据"}]},
  "challenge_checks": {"verdict": "PASS", "checks": [{"location": "被质疑的具体判断", "assessment": "反证检查结论", "basis": "原始依据与限制"}]},
  "issues": [],
  "verdict": "PASS"
}
```

返工意见包含location、problem、required_change、status和resolution。status为open、resolved或not_applicable，关闭意见必须有实际改写或不适用依据。复审同时记录旧句和新句，单纯补录证据不得宣称正文完成重写。比较上一版与本版Word正文，正文相同则明确记录“正文未变”，重新判断此前文字问题是否仍然存在。

将已审 Word 放入交付目录后，正式定稿必须针对该目录中的实际文件执行以下命令。交付文件再保存、重新生成或替换后，重新核对当前成品。哈希不符时，先确认变化并按实际稿件复核，不得只修改评审记录的哈希。

```bash
python <SKILL_DIR>/scripts/check_deliverables.py --minutes <当前Word> --expected-data <normalized-data.json> --final-review <minutes-review-result.json>
```

涉及Excel时继续附加原有台账及计算检查参数。命令拒绝版本绑定不符、未通过两维度评审、缺少逐段依据或未闭合意见的结果。程序检查记录完整性与版本绑定，评审者承担语义判断和独立性真实性责任。草稿可继续使用原有生成与检查命令，正式交付按本节入口验收。

## v3：实质质疑与取舍验收

第一遍检查项目内部口吻：本项目主体是否被泛称“客户方业务负责人”；第二遍核对替换后的部门、职务或姓名是否真实。不得仅删去“客户方”却留下未经确认的“负责人”。实际业务客户称谓不误删。

逐项评审“跟踪事项”的重要性、共同处理必要性、具体处理要求，以及与已约定行动的重复；同时检查移出的关键问题是否仍有承接。完整候选清单及保留/归并/移出理由须交给评审者。每项必须留下判断依据，没有跟踪事项也要解释筛选范围。

评审者主动寻找：最可能超出证据的结论；原文中可能反驳概述的限制或例外；被遗漏的重要要求；重复但未形成业务认识的段落；仅影响写稿、不影响项目的跟踪项。不是必须找出错误，但必须记录检查了哪一具体判断、如何回查、结果是什么，不能只写“无问题”。

在现有JSON增加三个必填对象，每个包含verdict（PASS或REVISE）和非空checks数组；每条含location、assessment、basis：
- synthesis：核对业务归纳稿与正文的组织关系、关系证据、重复与遗漏，并记录归纳稿位置。
- tracking_selection：核对候选事项取舍记录、最终关键事项及移出项的承接。没有候选时记录检查范围与不适用依据。
- challenge_checks：评审者独立选取高风险判断开展反证检查，包含当前正文位置、原始材料定位及是否推翻/限制该判断。

任一维度REVISE均不得定稿。意见须含具体位置、原始依据、返修要求及验收条件。复审除关闭旧意见外，检查修改是否引入归属丢失、事实遗漏或新断言；保留旧句与新句。程序仅验证记录完整，不把写入三个对象视作实际完成语义评审。

## 逐节检查段落是否零碎

section_coherence 使用上述 JSON 的 verdict 和 checks 结构。每个正文业务小节至少一条记录，覆盖该节的编号范围，写明本节主线、各段各自承担的业务结论，以及相邻段为何合并或分开。可对独立条款、行动清单等注明适用的列表理由。评审依据须指向实际成品中的文字及相关事实。

如果同一业务结论的机制、条件或影响被拆成并列编号，读者需要自行重建关系，则判 REVISE，即使每条句子本身通顺、事实正确。指出应归并的编号以及重写后必须保留的事实、限制和归属。复审按整节通读，检查是否保留独立结论、是否丢失事实或引入未经支持的关系。不按句长或编号数量判定。
